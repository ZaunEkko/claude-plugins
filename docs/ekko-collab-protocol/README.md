# `ekko-collab-protocol` 使用指南

`ekko-collab-protocol` 帮软件项目建立并持续改进 Coding Agent 协作协议：让 Agent 接到一句自然语言需求后，知道先读什么、何时问人、需求和计划记在哪、怎么验证、做完同步什么，以及哪些操作必须经过授权。

插件内置离线的 [ekko-benchmark](../../plugins/ekko-collab-protocol/README.md#内置评分引擎) 评分引擎：只读、确定、不联网、不执行被测项目的命令。

## 三个命令

```text
/ekko-collab-protocol:init [项目目录]
/ekko-collab-protocol:score [项目目录]
/ekko-collab-protocol:optimize [项目目录]
```

不传目录时使用当前工作目录。

### `init`：一键初始化

1. 先扫描一次，记录基线分；
2. 读取项目结构：已有的 Agent 入口、Git 布局（单仓或多仓协作目录）、真实存在的构建与测试命令、主要目录、生成目录、文档语言；
3. 只就团队约定提问：Agent 能否自行创建本地 commit，以及必要时的文档语言和存放位置；push、merge、发布、打 tag、部署始终需要明确授权；
4. 生成确定性计划，展示每个 `CREATE` / `SKIP` 文件、渲染后的入口内容和计划摘要；
5. 你确认这份摘要后才写入；已存在的文件一律不覆盖。

默认生成：

| 文件 | 作用 |
|---|---|
| `AGENTS.md` | 协作入口：开工读取顺序、适用范围与目录、文档职责、澄清、决策、实施、验证、同步、边界与授权 |
| `CLAUDE.md` | 仅在不存在时创建，用 `@AGENTS.md` 导入入口，避免两份规则漂移 |
| `docs/STATUS.md` | 当前任务状态；初始为空闲，开始任务后记录进度、阻塞、验证结果和下一步 |
| `docs/changes/README.md` | 需求记录约定：需求、实施计划、验收标准与验证记录写在同一文件，附模板 |
| `docs/adr/README.md` | 决策记录约定：只记录用户确认的关键取舍，变化时新建并注明替代关系 |

中文和英文模板逐句对应。还没开始写代码、只有协作文档的项目同样适用；建立工程后再扫描即可核对命令。

### `score`：打分

只读地输出两个分数：

- **静态协议分**：确定性、可复现的基线；
- **Agent 语义分**：当前 Agent 按评分协议逐条阅读项目后的独立判断，可以加分也可以降分，每个改判都附 `file:line` 证据。

报告还包含九个维度分、核心链路诊断、未读范围和改进建议。打分不会修改任何文件。

### `optimize`：自动优化

1. 先只读打分（同一会话里已有的结果会复用）；
2. 把未通过项分为三类并排序：
   - **客观错误**：失效链接、不存在的脚本、被提交的凭据文件等，按事实修复；
   - **真实缺口**：协议确实缺少的能力，核心规则单独标出；
   - **扫描器漏判**：能力已存在、只是写法没被规则识别，不会建议你改写文档迎合规则，只作为 ekko-benchmark 的反馈；
3. 每条给出写入位置、最小改动草稿和预计涨分，由你勾选要应用的条目；
4. 授权、可写范围、确认流程等团队承诺只有你选中后才写入；
5. 修改后重新打分，报告改前、改后两组分数。

插件不会执行 `git add`、`git commit` 或任何远程操作。

## 安装

```text
/plugin marketplace add ZaunEkko/claude-plugins
/plugin install ekko-collab-protocol@zaunekko
/reload-plugins
```

运行环境需要 Node.js 22 或更高版本。

## 边界与隐私

- 评分引擎离线运行，不访问网络，不调用外部模型；语义评分由你当前会话中的 Agent 完成。
- 不跟随符号链接，不读取工作区外文件，不输出疑似凭据原文。
- `init` 的配置文件写在系统临时目录，不进入项目；写入前校验路径必须位于项目内且不经过符号链接。
- 静态分只表示协作协议的完备度，不代表代码质量、模型能力或真实任务成功率。
